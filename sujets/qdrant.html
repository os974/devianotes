Qdrant

Une base de données vectorielle open-source écrite en Rust : stocker des embeddings (vecteurs de nombres) et retrouver les plus proches d'une requête en quelques millisecondes. La brique centrale d'un RAG performant, plus puissante que FAISS et plus simple à déployer qu'un Postgres+pgvector.

À quoi ça sert

Une base vectorielle stocke des points dans un espace à N dimensions (typiquement 384, 768 ou 1536) et sait répondre à la question « quels sont les 10 points les plus proches de ce vecteur ? » en quelques millisecondes, même sur des millions de points.

Pourquoi on veut ça : les embeddings d'un modèle (cf. Hugging Face sentence-transformers, Ollama nomic-embed-text…) transforment un texte/image en vecteur, où deux contenus sémantiquement proches ont des vecteurs proches. Du coup, retrouver « les documents qui parlent du même sujet » = recherche dans un espace vectoriel.

  • RAG (Retrieval-Augmented Generation) — pour chaque question d'un chatbot, on retrouve les passages pertinents et on les passe en contexte au LLM.
  • Recommandation — « produits similaires », « si tu as aimé X, regarde Y ».
  • Recherche sémantique — un moteur de recherche qui comprend le sens, pas juste les mots-clés.
  • Déduplication / clustering — regrouper des contenus presque identiques à grande échelle.

Spécificités de Qdrant :

  • Recherche vectorielle + filtres sur les métadonnées (« les chunks du document X qui parlent de Y »).
  • Payload typé — chaque vecteur peut porter un dict JSON arbitraire (titre, source, date…).
  • Quantification — réduire l'usage mémoire d'un facteur 4-32× au prix d'une légère perte de précision.
  • Distribué — sharding et réplication intégrés pour les gros volumes.
  • API REST + gRPC + client Python typé avec Pydantic.
Qdrant, Chroma, Weaviate, pgvector, FAISS… c'est quoi la différence ?

FAISS = librairie en mémoire de Meta, idéal pour prototyper en local mais pas une vraie base. Chroma = très simple, Python-first, parfait pour les démos. Qdrant = serveur prod-ready, meilleur compromis perf/simplicité, écrit en Rust. Weaviate = équivalent Qdrant, avec plus de features intégrées (modules d'embedding internes). pgvector (extension PostgreSQL) = parfait si tu as déjà Postgres et n'as pas envie d'un service en plus, mais moins performant à grande échelle. Pour un nouveau projet RAG, Qdrant est un excellent défaut.

Un exemple d'usage

Lancer Qdrant en local, créer une collection, ajouter quelques textes embeddés via Ollama, faire une recherche sémantique :

bash 
docker run -d --name qdrant -p 6333:6333 -p 6334:6334 \
  -v qdrant_storage:/qdrant/storage \
  qdrant/qdrant
python 
from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams, PointStruct
import httpx

client = QdrantClient(url="http://localhost:6333")

# Créer une collection (768 dim pour nomic-embed-text)
client.create_collection(
    collection_name="docs",
    vectors_config=VectorParams(size=768, distance=Distance.COSINE),
)

# Calculer des embeddings via Ollama
def embed(text):
    r = httpx.post("http://localhost:11434/api/embeddings",
                  json={"model": "nomic-embed-text", "prompt": text})
    return r.json()["embedding"]

textes = [
    "Python est un langage de programmation interprété.",
    "FastAPI permet de créer des APIs Python rapides.",
    "La pâte à crêpes se fait avec farine, œufs et lait.",
]
client.upsert(
    collection_name="docs",
    points=[PointStruct(id=i, vector=embed(t), payload={"text": t})
            for i, t in enumerate(textes)],
)

# Recherche sémantique
result = client.query_points(
    collection_name="docs",
    query=embed("comment faire une API en Python ?"),
    limit=2,
)
for point in result.points:
    print(point.score, point.payload["text"])
# > 0.78 "FastAPI permet de créer des APIs Python rapides."
# > 0.55 "Python est un langage de programmation interprété."

Le résultat est ordonné par similarité décroissante. La phrase sur les crêpes a un score très bas, donc elle est exclue. Tout ça sans aucun mot-clé en commun avec la requête — Qdrant cherche par sens.

How-to : installer et utiliser Qdrant

  1. Lancer le serveur Qdrant

    Comme PostgreSQL/MongoDB, l'image Docker officielle est la voie royale (cf. Docker) :

    bash 
    docker run -d --name qdrant \
  -p 6333:6333 \
  -p 6334:6334 \
  -v qdrant_storage:/qdrant/storage \
  qdrant/qdrant:latest

    6333 = REST, 6334 = gRPC. Le dashboard web est sur http://localhost:6333/dashboard.

    Mode embedded pour tester

    Le client Python sait aussi tourner « en mémoire » sans serveur : QdrantClient(":memory:") ou QdrantClient(path="./qdrant_data") pour persister sur disque. Pratique pour les tests pytest ou les notebooks.

  2. Installer le client Python

    bash 
    uv add qdrant-client

  3. Créer une collection

    Une collection est l'équivalent d'une table. Il faut décider à la création : la dimension des vecteurs (dépend du modèle d'embeddings utilisé) et la métrique de distance (Cosine pour du texte, Euclidienne pour des images, Dot product pour les modèles normalisés).

    python 
    from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams

client = QdrantClient(url="http://localhost:6333")

client.create_collection(
    collection_name="articles",
    vectors_config=VectorParams(
        size=768,                # dim du modèle d'embeddings
        distance=Distance.COSINE,
    ),
)

  4. Ajouter des points (upsert)

    upsert = insert ou update si l'ID existe. Chaque point a un id, un vector, et optionnellement un payload (métadonnées).

    python 
    from qdrant_client.models import PointStruct

client.upsert(
    collection_name="articles",
    points=[
        PointStruct(
            id=1,
            vector=[0.1, 0.2, ...],     # 768 floats
            payload={"title": "Intro", "author": "Alice", "year": 2026},
        ),
        PointStruct(id=2, vector=[...], payload={"title": "Suite", ...}),
    ],
)

    L'id peut être un int ou un UUID. Le payload est un dict JSON arbitraire, indexable pour les filtres.

  5. Rechercher avec ou sans filtre

    python 
    # Recherche simple
result = client.query_points(
    collection_name="articles",
    query=query_vector,
    limit=5,
)

# Recherche avec filtre sur le payload
from qdrant_client.models import Filter, FieldCondition, MatchValue

result = client.query_points(
    collection_name="articles",
    query=query_vector,
    query_filter=Filter(must=[
        FieldCondition(key="year", match=MatchValue(value=2026)),
        FieldCondition(key="author", match=MatchValue(value="Alice")),
    ]),
    limit=5,
)

for p in result.points:
    print(p.id, p.score, p.payload)

    Les filtres se combinent avec must (AND), should (OR), must_not (NOT). Qdrant applique les filtres efficacement en parallèle de la recherche vectorielle.

  6. Mettre à jour ou supprimer

    python 
    # Re-upsert avec le même ID = update
client.upsert(collection_name="articles",
              points=[PointStruct(id=1, vector=new_vec, payload={...})])

# Modifier juste le payload
client.set_payload(collection_name="articles",
                   payload={"reviewed": True}, points=[1, 2])

# Supprimer
client.delete(collection_name="articles", points_selector=[1, 2])

  7. Indexer une colonne du payload (filtres rapides)

    Si tu filtres souvent sur un champ, créer un index dessus accélère drastiquement :

    python 
    from qdrant_client.models import PayloadSchemaType

client.create_payload_index(
    collection_name="articles",
    field_name="year",
    field_schema=PayloadSchemaType.INTEGER,
)

  8. Branchement aux frameworks RAG

    LangChain et LlamaIndex supportent Qdrant comme vector store en quelques lignes. Pas besoin d'écrire le code d'upsert/search à la main.

    python (LangChain) 
    from langchain_qdrant import QdrantVectorStore
from langchain_ollama import OllamaEmbeddings

embeddings = OllamaEmbeddings(model="nomic-embed-text")
store = QdrantVectorStore.from_documents(
    documents=docs,
    embedding=embeddings,
    url="http://localhost:6333",
    collection_name="rag_docs",
)
retriever = store.as_retriever(search_kwargs={"k": 4})

Qdrant et le reste de l'écosystème

  • Ollama / Hugging Face — producteurs des embeddings que Qdrant stocke. Le plus simple : Ollama + nomic-embed-text pour des embeddings locaux sans clé d'API.
  • LangChain / LlamaIndex — consommateurs principaux. Les deux frameworks ont des intégrations Qdrant prêtes à l'emploi pour le RAG.
  • PostgreSQL — alternative via l'extension pgvector. À choisir si tu as déjà Postgres et que tes besoins vectoriels sont modestes.
  • Docker / Kubernetes — Qdrant se déploie comme conteneur. Pour la haute dispo, sa version cloud ou un cluster Kubernetes avec son operator.
  • FastAPI — pattern type : endpoint POST /search qui embed la requête avec Ollama et interroge Qdrant. Latence totale 50-100 ms.
  • Pydantic — le client Python qdrant-client utilise Pydantic en interne pour les modèles (PointStruct, Filter…). Tu profites de l'auto-complétion et de la validation.
  • DVC — pour versionner un dump Qdrant à un moment T. Utile quand l'état du vector store fait partie de ce qu'on doit pouvoir reproduire.
Dimension : à ne pas changer après coup

La size du VectorParams est figée à la création de la collection. Si tu changes de modèle d'embeddings (768 → 1024 dim par exemple), il faut recréer la collection et re-embedder tous les documents. Cf. le piège équivalent dans la fiche LlamaIndex.
