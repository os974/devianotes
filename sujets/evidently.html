Evidently

La lib open-source pour surveiller la dérive (drift) d'un modèle ML en production. Compare les données qui arrivent aux données d'entraînement, mesure la dégradation des prédictions, génère des rapports lisibles. Le maillon entre « j'ai déployé un modèle » et « je sais quand il faut le ré-entraîner ».

À quoi ça sert

Un modèle entraîné sur les données de janvier ne reste pas indéfiniment performant : en juin, le profil des utilisateurs change, les saisons influent, le marché évolue. Sans surveillance, le modèle continue de prédire silencieusement avec une qualité qui dégrade. Evidently mesure cette dérive et te signale quand intervenir.

Trois types de dérive à surveiller :

  • Data drift — la distribution des features change. Ex : l'âge moyen des utilisateurs passe de 35 à 45 ans.
  • Target drift — la distribution de la cible change. Ex : le taux de churn double.
  • Prediction drift — la distribution des sorties du modèle change. Ex : le modèle prédit de plus en plus de « refus ».

Concrètement, Evidently te donne :

  • Reports HTML — un fichier .html auto-contenu, partageable, avec graphiques interactifs des distributions et des métriques de drift.
  • Tests — assertions pass/fail à intégrer en CI ou dans un pipeline Prefect (« drift > 5% sur la feature X → alerte »).
  • Snapshots JSON — métriques structurées qu'on peut stocker, comparer dans le temps, ou pousser dans Prometheus/Grafana.
  • Cloud monitoring (optionnel, payant) — UI dédiée pour suivre plusieurs modèles en continu. La version OSS reste largement suffisante pour démarrer.
Drift monitoring vs simple métrique de performance ?

Calculer juste l'accuracy en prod ne suffit pas : il faut les vraies étiquettes, qui arrivent souvent avec un délai (le ground truth d'un crédit accordé n'est connu que des mois plus tard). Le drift permet d'alerter avant même d'avoir les vraies étiquettes — si les données d'entrée diffèrent trop de celles vues à l'entraînement, on peut prédire la dégradation sans attendre les labels.

Un exemple d'usage

Comparer un dataset de référence (les données d'entraînement) à un dataset courant (les données reçues en prod la semaine dernière), générer un rapport HTML interactif :

python 
import pandas as pd
from evidently import Report
from evidently.presets import DataDriftPreset

reference = pd.read_csv("data_train.csv")         # données d'entraînement
current = pd.read_csv("data_prod_semaine.csv")   # données récentes

report = Report(metrics=[DataDriftPreset()])
result = report.run(reference_data=reference, current_data=current)

# Sauver le rapport HTML interactif (à ouvrir dans un navigateur)
result.save_html("drift_report.html")

# Récupérer les métriques en JSON pour l'envoyer à un système d'alerting
import json
metrics = json.loads(result.json())
print(metrics["metrics"][0])

Le HTML produit montre pour chaque feature : sa distribution référence vs courante, le score de drift (différence statistique), un verdict (drifté ou non). En 30 secondes tu sais quels champs ont bougé.

How-to : installer et utiliser Evidently

  1. Installer Evidently

    Dépendance principale (s'utilise dans le code de surveillance, cf. UV) :

    bash 
    uv add evidently

  2. Préparer un dataset de référence

    Tu as besoin de deux DataFrames pandas avec les mêmes colonnes : les données d'entraînement (référence) et les données récentes en prod (courant). La référence sert de baseline figée — la même pendant des mois.

    python 
    import pandas as pd

reference = pd.read_csv("data/train.csv")
current = pd.read_csv("data/prod_last_week.csv")

# Très important : mêmes colonnes, mêmes types
assert set(reference.columns) == set(current.columns)

  3. Le pattern Report + Preset

    Report est l'objet principal. On le configure avec une liste de metrics ou de presets (groupes de métriques prêts à l'emploi).

    python 
    from evidently import Report
from evidently.presets import (
    DataDriftPreset,         # dérive des features
    DataSummaryPreset,       # stats descriptives
    RegressionPreset,        # perf modèle régression
    ClassificationPreset,    # perf modèle classif
)

report = Report(metrics=[
    DataDriftPreset(),
    DataSummaryPreset(),
])
result = report.run(reference_data=reference, current_data=current)

  4. Métriques de dérive individuelles

    Pour aller plus fin que les presets, on choisit des métriques précises :

    python 
    from evidently import Report
from evidently.metrics import (
    ValueDrift, DriftedColumnsCount, MissingValueCount,
)

report = Report(metrics=[
    ValueDrift(column="age"),                  # drift sur 1 colonne
    DriftedColumnsCount(),                       # nb total de colonnes en drift
    MissingValueCount(column="revenue"),         # valeurs manquantes
])
result = report.run(reference_data=reference, current_data=current)

  5. Surveillance de la performance modèle

    Si tu as les vraies étiquettes, tu peux aussi mesurer la performance courante vs référence :

    python 
    from evidently import Report, DataDefinition
from evidently.presets import ClassificationPreset

# Indiquer à Evidently quelle colonne = prédiction, laquelle = vérité
schema = DataDefinition(
    classification=[{"target": "y_true", "prediction": "y_pred"}]
)

report = Report(metrics=[ClassificationPreset()])
result = report.run(reference_data=ref, current_data=cur,
                    data_definition=schema)
result.save_html("perf_report.html")

  6. Tests : passer en mode pass/fail

    Pour intégrer Evidently dans un pipeline (CI ou Prefect), on veut un verdict booléen plutôt qu'un rapport visuel :

    python 
    from evidently import Report
from evidently.metrics import DriftedColumnsCount
from evidently.tests import lte

report = Report(
    metrics=[DriftedColumnsCount(tests=[lte(3)])],   # ≤ 3 colonnes en drift
)
result = report.run(reference_data=ref, current_data=cur)

if not result.passed():
    raise RuntimeError("Drift critique détecté, ré-entraînement requis")

  7. Automatiser : Prefect + Evidently

    Le pattern type : un flow Prefect qui tourne tous les jours, charge les données récentes, génère le rapport, alerte si drift critique.

    python 
    from prefect import flow, task
from evidently import Report
from evidently.presets import DataDriftPreset

@task
def audit_drift(ref, cur):
    r = Report(metrics=[DataDriftPreset()])
    res = r.run(reference_data=ref, current_data=cur)
    res.save_html(f"reports/drift_{datetime.now():%Y-%m-%d}.html")
    return res

@flow
def weekly_monitoring():
    ref = load_reference()
    cur = load_last_week()
    res = audit_drift(ref, cur)
    if not res.passed():
        notify_slack("⚠ Drift détecté, voir reports/")

  8. Pousser les métriques vers Grafana

    Pour visualiser l'évolution dans le temps (et pas seulement au moment T), on extrait les métriques en JSON et on les envoie à Prometheus ou un endpoint custom consommé par Grafana :

    python 
    import json

metrics = json.loads(result.json())["metrics"]
for m in metrics:
    push_to_prometheus(
        metric_name=m["metric_id"],
        value=m["value"],
        labels={"model": "churn_v1"},
    )

Aide-mémoire

from evidently import Report
from evidently.presets import DataDriftPreset

r = Report(metrics=[DataDriftPreset()])
res = r.run(reference_data=ref, current_data=cur)
res.save_html("drift.html")
res.json()                       # métriques en JSON
res.passed()                     # True/False si tests configurés
python (presets utiles) 
from evidently.presets import (
    DataDriftPreset, DataSummaryPreset,
    ClassificationPreset, RegressionPreset,
)
python (test pass/fail) 
from evidently.metrics import DriftedColumnsCount
from evidently.tests import lte, gte

Report(metrics=[DriftedColumnsCount(tests=[lte(3)])])

Evidently et le reste de l'écosystème

  • MLflow — combo naturel : MLflow track l'entraînement, Evidently track la prod. On peut logger un rapport Evidently comme artifact d'un run MLflow pour garder la trace de l'état des données au moment du déploiement.
  • Prefect — l'orchestrateur qui lance Evidently sur un calendrier (quotidien, hebdo) et déclenche le ré-entraînement si le drift franchit un seuil. C'est le pattern « MLOps mature ».
  • Grafana / Prometheus — pour visualiser l'évolution des métriques de drift dans le temps (et pas juste un snapshot), on pousse les métriques Evidently dans Prometheus.
  • pandas / Polars — Evidently consomme et produit des DataFrames pandas. Polars est supporté en convertissant (df.to_pandas()).
  • DVC — versionner le dataset de référence avec DVC : tu peux toujours rejouer un rapport Evidently sur la version exacte des données qui a servi de baseline au moment du déploiement.
  • FastAPI — exposer un endpoint /health/drift qui renvoie l'état drift courant, utilisable par un dashboard ou Uptime Kuma.
Le piège : choisir le bon dataset de référence

La référence doit être un dataset représentatif des conditions d'entraînement. Pas tes données de validation (trop petites), pas le dataset le plus récent (trop proche du courant). Le bon choix : un échantillon stratifié du training set, versionné dans DVC, jamais modifié.
