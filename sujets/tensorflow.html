TensorFlow

Le framework de deep learning de Google, et son API haut niveau Keras. Concurrent direct de PyTorch, moins dominant aujourd'hui côté recherche mais toujours présent en production, en mobile (TF Lite) et dans tout l'écosystème Google. À connaître pour lire le code des modèles plus anciens et savoir choisir entre les deux.

À quoi ça sert

TensorFlow sert à entraîner et déployer des réseaux de neurones en Python (et au-delà). Comme PyTorch, il propose des tenseurs accélérés GPU/TPU, du calcul automatique des gradients et une bibliothèque de couches prêtes à l'emploi. Sa particularité historique : un graphe de calcul optimisé pour le déploiement.

En pratique, on l'utilise presque toujours via Keras, l'API haut niveau intégrée depuis TF 2.0 :

  • tf.Tensor — le tableau multi-dim équivalent du tensor PyTorch et du NumPy ndarray.
  • tf.keras.Sequential / Model — la façon de définir un modèle : on empile des couches, on appelle compile() puis fit().
  • tf.data.Dataset — un pipeline de données performant pour streamer, mélanger, batcher des données vers le modèle.
  • SavedModel — le format d'export universel pour servir le modèle (TF Serving, TF Lite, TensorFlow.js).
TensorFlow vs PyTorch : lequel choisir en 2026 ?

En 2026, PyTorch domine largement la recherche (la quasi-totalité des papiers récents) et de plus en plus l'industrie. TensorFlow reste pertinent dans trois cas : code legacy (beaucoup de pipelines Google et grands groupes), mobile / embarqué (TF Lite est plus mature que les alternatives PyTorch), et écosystème Google (TPU, Vertex AI). Si tu démarres un projet sans contrainte particulière, PyTorch est généralement le meilleur choix. Si tu rejoins une équipe TF existante, sa stack est très solide aussi.

Un exemple d'usage

Le « hello world » deep learning : un classifieur sur MNIST en quelques lignes avec Keras.

python 
import tensorflow as tf
from tensorflow import keras

# 1) Charger les données (intégré dans Keras)
(X_train, y_train), (X_test, y_test) = keras.datasets.mnist.load_data()
X_train, X_test = X_train / 255.0, X_test / 255.0

# 2) Définir le modèle (séquence de couches)
model = keras.Sequential([
    keras.layers.Flatten(input_shape=(28, 28)),
    keras.layers.Dense(128, activation="relu"),
    keras.layers.Dropout(0.2),
    keras.layers.Dense(10, activation="softmax"),
])

# 3) Compiler (loss + optimiseur + métriques)
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

# 4) Entraîner
model.fit(X_train, y_train, epochs=5, validation_split=0.1)

# 5) Évaluer
loss, acc = model.evaluate(X_test, y_test)
print(f"accuracy test : {acc:.2%}")

Le pattern à retenir : Sequential → compile → fit → evaluate. C'est ce qui différencie le plus TensorFlow/Keras de PyTorch : la boucle d'entraînement est cachée dans fit(), là où PyTorch te demande d'écrire la boucle à la main. Plus rapide à démarrer, moins flexible quand on veut customiser.

How-to : installer et utiliser TensorFlow

  1. Installer TensorFlow

    Avec UV, version CPU (suffisante pour apprendre) :

    bash 
    uv add tensorflow
    GPU NVIDIA, Apple Silicon, autres

    Sur Linux avec une carte NVIDIA, le package tensorflow inclut le support CUDA depuis TF 2.14. Sur Apple Silicon (M1/M2/M3), installer tensorflow-macos + tensorflow-metal pour l'accélération GPU. Sur Windows natif, TensorFlow n'a plus de support GPU depuis 2.10 — il faut passer par WSL2.

  2. Manipuler des tenseurs

    python 
    import tensorflow as tf

# Créer des tenseurs
t = tf.constant([[1., 2.], [3., 4.]])
tf.zeros((3, 4)); tf.ones(10); tf.random.normal((3, 4))

# Inspection
t.shape, t.dtype, t.device

# Opérations vectorisées (comme NumPy)
t + 1; t * 2; tf.matmul(t, tf.transpose(t))

# Conversion NumPy ↔ TensorFlow
import numpy as np
arr = t.numpy()                       # tf → array
t2 = tf.convert_to_tensor(arr)         # array → tf

  3. Construire un modèle Keras

    Trois styles, du plus simple au plus flexible :

    python 
    # 1) Sequential — empilement linéaire
model = keras.Sequential([
    keras.layers.Dense(64, activation="relu", input_shape=(10,)),
    keras.layers.Dense(3, activation="softmax"),
])

# 2) Functional API — graphe (multi-entrées, branches)
inputs = keras.Input(shape=(10,))
x = keras.layers.Dense(64, activation="relu")(inputs)
outputs = keras.layers.Dense(3, activation="softmax")(x)
model = keras.Model(inputs, outputs)

# 3) Subclassing — comme nn.Module en PyTorch
class MLP(keras.Model):
    def __init__(self):
        super().__init__()
        self.d1 = keras.layers.Dense(64, activation="relu")
        self.d2 = keras.layers.Dense(3, activation="softmax")

    def call(self, x):
        return self.d2(self.d1(x))

  4. Compiler et entraîner

    python 
    model.compile(
    optimizer=keras.optimizers.Adam(learning_rate=1e-3),
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"],
)

history = model.fit(
    X_train, y_train,
    epochs=20,
    batch_size=32,
    validation_data=(X_val, y_val),
    callbacks=[
        keras.callbacks.EarlyStopping(patience=3, restore_best_weights=True),
    ],
)

    L'objet history contient les courbes loss/metrics par epoch, faciles à tracer avec matplotlib.

  5. Pipeline de données avec tf.data

    Pour des datasets qui ne tiennent pas en mémoire ou pour des transformations à la volée :

    python 
    ds = tf.data.Dataset.from_tensor_slices((X_train, y_train))
ds = (ds
      .shuffle(buffer_size=10_000)
      .batch(32)
      .prefetch(tf.data.AUTOTUNE))

model.fit(ds, epochs=5)

  6. Évaluer et prédire

    python 
    loss, acc = model.evaluate(X_test, y_test)

probs = model.predict(X_new)               # shape (N, n_classes)
preds = probs.argmax(axis=1)

  7. Sauvegarder et recharger

    Depuis Keras 3, le format recommandé est .keras (un zip contenant l'architecture, les poids et l'état de l'optimiseur) :

    python 
    # Sauver tout le modèle
model.save("model.keras")

# Recharger
model = keras.models.load_model("model.keras")

# SavedModel (format pour TF Serving / déploiement)
model.export("saved_model/")

  8. Aller plus bas : GradientTape

    Quand fit() ne suffit plus (custom training loop, GAN, RL), on écrit la boucle à la main avec tf.GradientTape — l'équivalent d'autograd en PyTorch :

    python 
    optimizer = keras.optimizers.Adam(1e-3)
loss_fn = keras.losses.SparseCategoricalCrossentropy()

for epoch in range(5):
    for xb, yb in train_ds:
        with tf.GradientTape() as tape:
            pred = model(xb, training=True)
            loss = loss_fn(yb, pred)
        grads = tape.gradient(loss, model.trainable_variables)
        optimizer.apply_gradients(zip(grads, model.trainable_variables))

TensorFlow et le reste de l'écosystème

  • PyTorch — le concurrent direct. Différence philosophique : Keras cache la boucle d'entraînement (fit()), PyTorch te la fait écrire à la main. Pour passer de l'un à l'autre, le concept (couches, loss, optimiseur, gradient) est identique, c'est le style d'API qui change.
  • NumPy — interopérable : t.numpy() et tf.convert_to_tensor(arr) partagent la même mémoire quand c'est possible.
  • scikit-learn — pour les modèles classiques sur données tabulaires de taille modeste, sklearn reste plus simple et plus rapide. TensorFlow devient pertinent dès qu'on attaque le deep learning ou des datasets massifs.
  • Hugging Face — beaucoup de modèles Transformers ont une variante TF (TFAutoModel) en plus de la version PyTorch. Pour les modèles récents, la version PyTorch est généralement mieux maintenue.
  • MLflow — mlflow.tensorflow.log_model(model, "model") sauvegarde un modèle Keras comme artifact de run, prêt à être servi.
  • FastAPI — pour exposer un modèle TF en API : on charge le modèle au démarrage, chaque requête fait model.predict(input). Pour un débit plus élevé, TF Serving (gRPC + REST) est conçu pour ça.
TF Lite, TF.js, TF Serving

L'écosystème TensorFlow brille au déploiement : TF Lite pour mobile / embarqué (Android, iOS, Raspberry Pi), TensorFlow.js pour exécuter le modèle dans un navigateur, TF Serving pour servir des modèles à grand débit en production. C'est dans cet espace que TF garde une longueur d'avance sur PyTorch.
